# Limitations and scope

This document records what the reference lab does not claim. Findings that were
specific to the earlier 0.15 experiment have either been corrected through the
0.16 public consumer surface or retained below where they still apply.

## Benchmark coverage

- The Britannia lane uses `rbac_with_abac_guard`. Its 3,209 cells do not exercise
  ReBAC as a selected decision mechanism.
- The 14-case adversarial lane is intentionally small and single-factor. It
  provides discriminating tenant, scope, binding, time, clearance, and
  composition cases, not exhaustive enterprise IAM coverage.
- Empty metric denominators remain visible. They are not converted to zero or
  one and are not folded into an aggregate.
- Metrics described as world properties are computed from evaluator truth alone;
  they characterize the generated world rather than the system under test.
- Some mechanism-specific submission fields are not derivable from public
  artifacts, including evaluator-minted derivation-path identifiers. They are
  reported as not publicly winnable rather than credited to the product.

## Britannia topology mapping

The input is a service, vendor, and deployment topology; SynthWorld's importer is
an identity/access blueprint. The adapter therefore makes explicit,
experiment-owned transformations. It is not a general topology compiler.

The detailed ledger records 100 field paths and their treatment. Important
losses include operational SLA/cost/network detail that has no identity or
authorization meaning in the released schema. Cross-tenant ownership and service
dependency pairs cannot be declared directly by the importer; they are preserved
as experiment metadata and inform the ABAC boundary cohort.

Population size is scaled by a configured divisor of 50. The source headcount is
preserved in the mapping ledger, but the compiled world is not a one-record-per-
employee digital twin.

## Policy design

- The Britannia cross-tenant ABAC rule uses public cell scope because the
  underlying ABAC predicate vocabulary does not express negated tenant equality.
  Rego independently derives tenant inequality as a cross-check, but that
  derivation is not the rule's control input.
- The public Britannia rules intentionally expose their scope. Public policy is
  an input to the PDP, not evaluator truth.
- The Britannia wrong-binding-named class is confounded by RBAC path absence.
  Dedicated binding accuracy should be read from the adversarial reference lane.
- Topaz identity is supplied with `IDENTITY_TYPE_MANUAL`; this lab does not test
  OAuth, CIMD, EMA, ID-JAG, token validation, or cross-organization trust
  propagation.
- The lab evaluates authorization decisions. It does not model enforcement after
  the PDP response, side effects, policy administration, or production audit
  retention.

## Topaz integration

The adapter targets the pinned Topaz 0.33.16 REST and directory semantics. It
loads individual objects and relations because this is the verified path for that
version. The result should not be assumed portable to later Topaz releases
without rerunning all structural checks.

Anonymous, no-TLS Topaz configuration is acceptable only because the service has
no published host ports and runs on an internal, ephemeral Compose network. It is
not a production deployment template.

The lab records exact load/read-back counts and product responses, but it is not
a performance benchmark. Timing fields are operational observations and are not
used for scoring.

## Isolation threat model

The runner receives no evaluator mount, and the scorer has no network. This
prevents evaluator access through the declared container capabilities and is
covered by a deliberate leakage regression.

It does not defend against an administrator controlling the Docker daemon or the
host. Such an administrator can replace images, change mounts, enter containers,
or read every bind-mounted artifact. Hostile-host assurance would require
separate trust domains and attestation.

The submission seal proves that scoring used exact predictions, public inputs,
policies, raw results, adapter source, product provenance, and isolation evidence.
It does not prove that Topaz itself is free from implementation vulnerabilities.

## Reproducibility boundary

Generation and projection are deterministic functions of committed inputs and
the pinned package. Product execution is expected to produce identical normalized
decisions; operational timing and container instance metadata are not benchmark
outputs.

The workflow requires Docker Compose and access to the pinned base and Topaz
images plus Python packages on the first build. Long-term archival requires
retaining those external blobs or mirroring them in a durable registry.

## Visualization

The self-contained HTML file is generated by experiment-owned Python from public
artifacts. It is not shipped by SynthWorld, is not a replacement for schema
validation, and contains no evaluator verdicts. Its leakage scan is an additional
guard, not the primary isolation mechanism.

## Safe interpretation

A perfect reference score means the pinned Topaz adapter and policy matched the
fixed evaluator truth on the stated cells and attempts. It does not imply that
Topaz, Rego, SynthWorld, or the mapping rules are universally correct, secure, or
production-ready.
